# Atlas Lite：普通人的多 Agent 工作法

> 为什么聊天式 Agent 不够，以及独立工作区如何带来可靠交付

<!-- slide: 01 -->

## ATLAS LITE · 普通人的多 AGENT 工作法

一个人，不该成为<br>
AI 团队的传话筒

**真正的多 Agent 工作法，<br>
不是多开几个聊天窗口。**

把复杂工作变成可见、可查、可交付的协作过程

<!-- slide: 02 -->

## 01 · 问题从哪里开始

聊天式 Agent 很聪明，<br>
却没有稳定的工作现场

- 背景资料放在哪里？
- 现在应该改哪个版本？
- 上次做到哪里，谁来继续？
- 正式成果？

聊天擅长回答问题；真实工作还要跨时间、跨角色，能够检查，也能够恢复。

<!-- slide: 03 -->

## 02 · 聊天一多，问题会放大

任务一多，四种混乱会一起出现

### 版本混乱

不知道哪份才是最新

### 责任混乱

不知道谁正在处理

### 完成混乱

说完成却无法验收

### 恢复混乱

中断后要重新解释

Agent 越多，人越像信息中转站。

<!-- slide: 04 -->

## 03 · 忙碌不等于产出

多开几个 Agent，不等于多做成几件事

- 所有人挤在同一张桌子
- 同一份工作
- 更多忙碌
- 更多交付

如果工作现场没有分开，增加 Agent 只会增加等待、覆盖和返工。

<!-- slide: 05 -->

## 04 · 第一个关键改变

独立工作区，就是给每个 Agent<br>
一间自己的工作室

**共同目标与资料**

### 研究工作室

只负责找事实

### 写作工作室

只负责做初稿

### 检查工作室

只负责找问题

大家共享同一个目标，但各自在自己的空间完成工作，互不覆盖、互不打断。

<!-- slide: 06 -->

## 05 · 独立之后，仍然需要秩序

独立不是各干各的，<br>
而是同一目标下的有序分工

**发现问题，就退回修改**

- 写清目标
- 拆开任务
- 独立完成
- 独立检查
- 正式交付

并行发生在中间；目标与验收仍然只有一套。

<!-- slide: 07 -->

## 06 · KFD 的核心理念

先有可靠事实，才有可靠合作

### KFD-1 · 事实不漂移

大家看到的是同一件事，<br>
不会各说各话。

### KFD-2 · 信任可检查

不是“相信我”，<br>
而是“你可以验证”。

### KFD-3 · 合作有价值

规则、选择和限制，<br>
都提前说清楚。

顺序很重要：没有事实，信任就没有地基。

<!-- slide: 08 -->

## 07 · ATLAS 如何把方法落到工作里

Atlas 把一次聊天，<br>
变成一条可以交付的工作链

- 你的目标
- 协调与拆分
- 独立任务 A
- 独立任务 B
- 独立任务 C
- 检查与汇总
- 正式成果

复杂性留给系统，判断权留给人。

<!-- slide: 09 -->

## 08 · 最终得到什么

你真正得到的，不是更多 Agent，<br>
而是五种工作价值

### 01 · 更多有效产出

只并行真正独立的任务

### 02 · 更少混乱

每个 Agent 都有独立现场

### 03 · 更可靠质量

有验收标准，也有独立检查

### 04 · 更容易恢复

过程留下可回看的记录

### 05 · 更低管理负担

系统负责派工、追踪和收口

诚实边界：不承诺固定倍数提速；先减少碰撞、返工和人工协调。

人负责方向，<br>
系统负责把工作做稳

### 你负责

目标 · 价值 · 优先级<br>

检查 · 记录 · 恢复
